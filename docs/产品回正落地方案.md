# 知序 AI · 产品回正落地方案（可执行版）

> 依据：组员 GPT 产品评审 + 当前可运行代码 + `HANDOFF.md` / `项目交付Todolist.md`  
> 原则：**不推翻重写**；以「系统学习 / 智能答疑」双入口收束；竞赛差异化 = **主动教学 + 动态案例演算 + 课程知识库答疑**。  
> 更新日期：2026-11-24

---

## 0. 一句话结论

评审指出的不是「再美化一下」，而是 **学习闭环被拆散、答疑页占了错误权重、动态案例亮点未做成演示级**。  
落地策略：**锁一条演示主路径，把 3 个差异化能力做透；其余只做必要补丁。**

---

## 1. 目标与非目标

### 1.1 本轮目标（验收一句话）

学生能在 **同一套浅色学习台** 里完成：

**打开知识点 → 听知知分段讲 → 中途提问不丢进度 → 调案例参数看结果变 → 做题/错题回流 → 全课答疑仍带课程上下文。**

录屏 6～8 分钟可完整演示上述链路（建议主打 **第九讲 TOPSIS** 或 **第二讲期望值**，二选一作主线）。

### 1.2 明确不做（避免再次跑偏）

| 不做 | 原因 |
|------|------|
| 再做一个独立「炫酷 AI 控制台」 | 偏离课程助教 |
| 答疑页右侧巨型数字人展台 | 占空间、无教学职责 |
| 浏览器内嵌原始 `.pptx` 编辑器 | 已有导出图；成本高 |
| 全方法 Solver 一次做完 | 只加深 1～2 个可演示方法 |
| 云口型 / 租用数字人换壳 | 二期；现用 TTS + 小窗即可 |
| 无上下文的通用工具（代码助手、生图等） | 与竞赛定位无关 |
| 大改首页成营销落地页 | 首页只做学习工作台 |

### 1.3 判断新需求的唯一标准

> 它是否帮助学生 **理解《决策理论与方法》**，并在录屏里 **30 秒内看懂差异**？  
> 否 → 不做或降为文案占位。

## 2. 现状对照（代码层）

| 评审诉求 | 现状 | 差距定性 |
|----------|------|----------|
| 双入口：系统学习 / 智能答疑 | 有目录、学习台、答疑空间、课件页 | **结构散**：课件页、学习台、答疑空间三套体验 |
| 数字人主动讲解 | 学习台步骤卡 + TTS；课件「请看第 N 页」 | 课件口播弱；学习台未成「播放器」 |
| 提问不离开学习位置 | 学习台内有追问；答疑空间是全屏跳转 | **页内答疑面板**未成为默认 |
| 动态案例调参实时算 | 期望值/不确定型有 Solver；TOPSIS 多是 walkthrough | **竞赛亮点未落地** |
| 答疑右侧辅助面板 | AskSpace 右侧偏形象展示 | 需改成关联知识/动作 |
| 复习闭环 | 有错题、复习页 | 「再做一题/同类新题」弱 |
| 浅色长读 UI | 学习台偏浅；答疑深色沉浸 | 答疑视觉与主站割裂 |
| 断点续学 | `localStorage` 进度有 | 首页工作台信息不足 |

**可复用资产（必须保留）：** FastAPI + DeepSeek RAG、期望值/不确定型 Solver、步骤卡、题库 JSON、课件导出图 `public/lectures/`、浮层知知、账号体系。

## 4. 分期落地（按周，可勾选）

### 阶段 P0 · 演示主线锁定（0.5～1 天）— **先做**

**产出：** 一页「录屏脚本 + 主打知识点」冻结表，全组统一。

- [ ] 选定主线 A 或 B（建议 **A：第九讲 TOPSIS**，差异化更强；若时间不够选 **B：第二讲期望值**）
- [ ] 写死 6～8 分钟脚本：首页 → 目录 → 学习台讲 2 步 → 调参看结果 → 页内提问 → 一道题 →（可选）全课答疑一句
- [ ] 冻结范围：P1～P3 只服务这条脚本；脚本外需求进「停车场」

**验收：** 组长/答辩人能按脚本口述，不即兴加功能。

---

### 阶段 P1 · 学习台改成「课程播放器」（3～5 天）— **最大头**

**改哪些文件（示意）：** `frontend/src/App.vue` 学习台区域、`AvatarPanel` / `SpiritFloat`、`LessonReadingPanel`；答疑抽屉可抽 `AskDrawer.vue`。

#### P1.1 页内结构（1.5～2 天）

- [ ] 学习台固定为：**主区内容 + 底部/侧边知知小窗 + 顶栏阶段 Tab**
  - Tab：`讲解` | `案例` | `练习`（错题挂练习 Tab 内）
- [ ] 讲解区：步骤卡图文为主；可选「本讲课件图」缩略条（复用 `/lectures/{ch}/`），**点击切页不离开学习台**
- [ ] 知知：**小窗**（展开面板可拖），职责 = 当前步口播字幕 + 暂停/继续 +「这里没听懂」
- [ ] **禁止**讲解时再跳进全屏答疑空间

#### P1.2 页内答疑抽屉（1～1.5 天）

- [ ] 「问知知」打开 **右侧/底部抽屉**，`method_id` + `section` + 当前步骤/案例上下文一并上传
- [ ] 关闭抽屉后 **进度、案例参数、播放位置均保留**
- [ ] 全课答疑入口仍保留在侧栏，但脚本里只作 20 秒彩蛋

#### P1.3 口播与步骤（0.5～1 天）

- [ ] 主线知识点：补齐 4～6 段可用 `speak`（步骤卡已有则抽检通顺度）
- [ ] 课件图模式：无文案时允许「请看第 N 页」；**演示主线不要靠课件页硬撑**

**验收：**

1. 从目录进主线知识点，不打开独立课件全屏也能讲完 2 步。  
2. 提问 → 回答 → 关闭，仍停在原步骤。  
3. 手机宽度下知知不挡主公式（可接受收起）。

---

### 阶段 P2 · 动态案例实验室（3～5 天）— **竞赛亮点**

**技术铁律：** LLM 只生成/解释；**数字只信 Solver。**

#### 若主线 = TOPSIS（推荐）

- [ ] 后端新增 `POST /compute/topsis`（标准化 → 加权 → 正负理想解 → 相对贴近度 → 排序）
- [ ] 单测：固定教材小数例，断言排序与 \(C_i\)（允许浮点误差）
- [ ] 前端案例实验室 UI（可先做在学习台「案例」Tab）：
  - [ ] 方案 × 指标表（只读或可改单元格，二选一；演示至少 **滑条改权重**）
  - [ ] 权重和归一（自动归一或校验 =1）
  - [ ] 「计算」按钮 → 调 Solver → 展示排序表 + 关键公式高亮
  - [ ] 「知知解释」：把 **Solver 结果 JSON** 塞进提示词，禁止模型重算
- [ ] 准备 1 个审过的默认案例 + 1 个可切换情境（文案可先写死）

#### 若主线 = 期望值（保底）

- [ ] 强化现有 `expected_value` 案例：切换案例、改收益/概率、实时重算、知知解释差值
- [ ] UI 提到「实验室」级：结果区对比「调整前 / 调整后」

**验收（录屏可拍）：**

1. 拖动权重（或改概率）→ 排序/最优方案 **肉眼可见变化**。  
2. 断网或关 Key 时，**计算区仍可用**；仅「解释」降级。  
3. 口播数字与面板数字一致。

---

### 阶段 P3 · 答疑页收权 + 复习补洞（2～3 天）

#### P3.1 AskSpace 改版（1～1.5 天）

- [ ] 去掉右侧大形象展台；改为 **可折叠「学习辅助」**：
  - 关联知识点（推荐已有 `recommend.js`）
  - 一键「进入学习台」
  - 快捷：通俗讲 / 完整推导 / 换案例解释 / 出一道练习（能接现有 ask/quiz 就接，接不上就灰掉）
- [ ] 语音：回答下方小控件即可
- [ ] 视觉：向学习台浅色靠拢（至少降低「另一网站」感；可先改背景与气泡，不做大视觉翻新）

#### P3.2 练习闭环（1 天）

- [ ] 「再做一题」：同 `bankId` 下一题（不是同一题刷新）
- [ ] 错题：保留题目 id、知识点、上次选项；「按步骤重讲」已有则打通到学习台讲解段
- [ ] 主线题库抽检 8～10 题，保证录屏不踩坑

**验收：** 答疑页截图不再出现「1/3 屏空数字人」；错题能回到对应知识点。

---

### 阶段 P4 · 首页工作台与目录（1～2 天，可与 P3 并行）

- [ ] 首页：继续学习、开始学习、答疑入口、**基于真实 progress/wrong 的 1～2 条建议**（去掉假统计）
- [ ] 目录：保持树 + 搜索；大卡片不扩张；显示已学/有错题标记即可
- [ ] 侧栏双入口文案统一：「课程学习」「智能答疑」

**验收：** 新用户 10 秒内知道点哪继续学。

## 6. 演示主线推荐脚本（可直接改数字）

### 推荐主线 A · TOPSIS（差异化强）

1. 首页点「继续学习 / 开始学习」  
2. 目录进「第九讲 · 正理想解与负理想解」（或 madm 对应 topic）  
3. 讲解 2 步：理想解含义 → \(C_i\) 公式  
4. 切「案例」：拖高某指标权重 → 排序变化  
5. 点「为什么变了」→ 知知按 Solver 结果解释  
6. 「这里没听懂」页内提问一句  
7. 练习 1 题 → 故意错 → 错题进复习  
8. （可选）侧栏进全课答疑，问「TOPSIS 为何要标准化」，点「进入对应课程」

### 保底主线 B · 期望值

同结构，案例改为改概率/收益看最优方案变化（现有 Solver）。

## 7. 接口与数据约定（P2 必须遵守）

```
LLM：情境文案、解释、答疑
Solver：一切数值、排序、最优方案
前端：只展示 Solver 返回；口播数字来自同一 JSON
```

答疑请求继续带：

- 学习台：`method_id` + `section` + `section_label`
- 全课：`method_id: "course"`
- 案例解释：附加 `compute_result` 摘要（最优方案、权重、排序前三）

课件教学文案：后续统一写入 `lectureDecks` 的 `narration`；**本轮不阻塞 P1～P2**。
